ข้อ 1 (ex1-callback.js) — ดึงข้อมูลด้วย Error-first Callback
สร้างฟังก์ชันค้นหานักศึกษาตาม ID โดยใช้วิธีดึงข้อมูลแบบรุ่นเก่า (Callback)
-ทำงานยังไง: ตรวจ ID ถ้าผิดปกติจะส่ง Error ออกทันที ถ้ารหัสถูกจะรอ 300ms แล้วส่งข้อมูลกลับ โดยมีกฎว่าพารามิเตอร์แรกของ callback ต้องเป็น error เสมอ (ถ้าไม่มี error ให้ส่ง null) และฝั่งเรียกใช้ต้องเช็ก if (error) ก่อนแตะข้อมูลเสมอ

ข้อ 2 (ex2-promise.js) — อัปเกรดเป็น Promise & ต่อโซ่
แปลงโค้ดจากข้อ 1 ให้เป็น Promise เพื่อแก้ปัญหา Callback ซ้อนกันจนอ่านยาก
-ทำงานยังไง: ใช้ new Promise โดยส่งผลลัพธ์ผ่าน resolve() (สำเร็จ) หรือ reject() (ล้มเหลว) รับผลด้วย .then() / .catch() / .finally() สามารถส่งต่อข้อมูลเป็นโซ่ 3 ขั้น (ดึงข้อมูล ➔ แปลงเกรด ➔ สร้างรายงาน) และมีตัวแปลง promisify() ช่วยเปลี่ยน callback เก่าให้กลายเป็น Promise อัตโนมัติ

ข้อ 3 (ex3-async-await.js) — เขียนแบบ async/await & เทียบความเร็ว
เขียนโค้ดจัดการข้อมูลให้อ่านง่ายเหมือนโค้ดปกติด้วย async/await และเปรียบเทียบการรันตามลำดับ vs ขนาน
-ทำงานยังไง:
    1.แบบตามลำดับ (for...of + await): รอโหลดทีละคน ช้ากว่า (~900ms)
    2.แบบขนาน (Promise.all + map): ส่งดึงข้อมูลพร้อมกัน รวบยอดทีเดียว เร็วกว่า (~300ms)
    3.safeReport: ใช้ try-catch-finally ครอบไว้เพื่อรับ Error และป้องกันไม่ให้โปรแกรมแครช

ข้อ 4 (ex4-combinators.js) — เลือกตัวจัดการ Promise ให้ถูกงาน
เลือกใช้เครื่องมือบริหาร Promise (Combinators) ให้เหมาะกับ 4 สถานการณ์จริง

ทำงานยังไง:
    1.Promise.all (โหลดหน้าแรก): ต้องสำเร็จครบทุกชิ้นเท่านั้น พังชิ้นเดียวคือล้มเหลวทันที
    2.Promise.allSettled (แจ้งเตือนผลสอบ): รอจนทำครบทุกช่องทาง ไม่ว่าตัวไหนจะสำเร็จหรือล้มเหลว ระบบก็ไม่พัง
    3.Promise.any (Mirror Server): เอาเฉพาะตัวที่สำเร็จเป็นคนแรก ตัวไหนล้มเหลวปล่อยผ่าน
    4.Promise.race (ค้นหาแบบกำหนดเวลา): วิ่งแข่งระหว่างการหาข้อมูลกับตัวจับเวลา (800ms) ใครถึงก่อนยึดผลลัพธ์ตัวนั้นทันที
